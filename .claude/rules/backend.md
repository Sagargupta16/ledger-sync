# Backend

Moved verbatim from the repo `CLAUDE.md` on 2026-10-31; repo-wide rules stay there. Paths and links below are relative to the repo root.

## Architecture

### Backend (`backend/src/ledger_sync/`)

Layered architecture:

- **`api/`** - FastAPI routers (auth, oauth, upload, money_manager_upload, upload_tokens, transactions, analytics, analytics_v2, calculations, preferences, account_classifications, categorization_rules, saved_views, exchange_rates, rates, stock_price, ai_chat, ai_tools, ai_usage, plus the 2.31.0 dashboard_metrics, weekly_recap, safe_to_spend, card_cycles, balance_checks, bank_alerts, review_queue, category_suggestions, rsu_tax, tax_deductions, tax_ais, cas_upload, semantic_search, push, mcp, and the 2.33.0 admin), with larger routers split into `*_impl/` packages or sibling helpers. `bank_alerts.py` also serves `POST /api/ingest/text`, `cas_upload.py` `/api/upload/cas` and `/api/mf-holdings`, and `mcp.py` `POST /mcp` (outside `/api`). `rates.py` serves `/api/rates/instruments` from `config/instrument_rates.json` (EPF/PPF/NPS rates with `effective_from` + `source_url` metadata). Routers are registered in `main.py`. Financial endpoints require JWT auth via `CurrentUser`; health, OAuth initiation/callback, and token refresh are public exceptions; `lsu_` token routes use `get_upload_principal` (Money Manager upload, which also takes a session) or `require_token_scope(scope)` (MCP, alert inbox), both in `deps.py`. `oauth.py` handles browser-bound, one-use Google/GitHub authorization code exchange with S256 PKCE; signed one-use state lives in `oauth_state.py` and provider config plus the PKCE-client guard in `oauth_providers.py`. AI configuration lives in `preferences_ai.py`. `ai_chat.py` proxies non-streaming Bedrock calls with app or personal bearer funding; model/credential resolution and invocation live in `ai_chat_bedrock.py`, bounded request models in `ai_chat_schemas.py`, and `ai_chat_thinking.py` supplies per-model Converse thinking fields (thinking off, or low effort where a model cannot turn it off), because reasoning blocks do not survive between tool rounds. `ai_tools.py` exposes `/api/ai/tools` and `/api/ai/tools/execute` for 16 read-only user-scoped tools with runtime argument validation. `ai_usage.py` reserves and settles Bedrock usage and records browser-direct usage reports. `admin.py` serves `GET /api/admin/stats` behind `require_admin` (email in `LEDGER_SYNC_ADMIN_EMAILS`, `core/admin_access.py`); `core/admin_stats.py` (with `admin_users.py` and `admin_app.py`) is the one place that reads across users on purpose: counts and sums, plus an accounts list with masked emails (`abc***@domain`) and per-account counts, never a row, amount or full email.
- **`core/`** - Business logic. `sync_engine.py` orchestrates `import_rows()` for JSON web uploads and `import_file()` for CLI file imports. `reconciler.py` handles user-scoped reconciliation and occurrence-aware SHA-256 IDs. `calculator.py` computes on-demand financial metrics. `analytics_engine.py` is a compatibility facade; the active analytics engine and rollup builders live under `core/analytics/`. `query_helpers.py` provides shared database-agnostic SQL aggregation helpers. `time_filter.py` holds the `TimeRange` presets. `ledger_clock.py` is the single source of naive IST `now`/`today`/month/FY boundaries -- never anchor a user-facing window on `datetime.now(UTC)`. Its frontend twin is `lib/dateKeys.ts` `getTodayKey(now?)` / `getCurrentMonth(now?)` (IST via `getLedgerTodayKey`): use them for any "today" or "this month", and `toLocalDateKey` only to format a given `Date`. `expense_class.py` holds the realised-capital-loss taxonomy that keeps trading losses out of consumption totals. `encryption.py` writes authenticated `ls-byok:v3:` AES-256-GCM envelopes derived with HKDF-SHA256 from `LEDGER_SYNC_ENCRYPTION_KEY`; authenticated legacy v1 PBKDF2 and v2 HKDF ciphertexts remain readable and can be rewrapped. `core/auth/` handles JWT token creation/verification. Each 2.31.0 domain has its own prefix family (`bank_alert_*` keeps hashes only, never the text; `safe_to_spend*`, `weekly_recap*`, `watch_tile*`, `card_cycles*`, `balance_check*`, `category_suggester*`, `foreign_assets*`, `push_*`, `cas_import.py` with `mf_*` and `amfi_nav.py`, `embeddings.py` with `semantic_search.py`). `dashboard_metrics*` ports the Dashboard's browser metrics with JavaScript-parity arithmetic: change it with `lib/ageOfMoneyCalculator.ts`, `lib/finance/investmentFlows.ts` and `components/analytics/health/*`, as with `metric_rules`. `category_override*` and `review_queue.py` replay Review Queue fixes on every import. In `core/analytics/`, `anomaly_*` are the detectors, `budget_tracking.py` is the month's spend per budget and `recurring_amounts.py` the user's amount beside the detected one.
- **`ingest/`** - Data ingestion pipeline used by CLI: `excel_loader.py` -> `normalizer.py` -> `validator.py` -> `hash_id.py`. The web upload path bypasses the file loaders -- frontend parses files client-side and sends structured JSON; `normalizer.normalize_from_dict()` handles dict-based normalization. `money_manager.py` is the exception: it reads a Money Manager `.mmbak` backup (Core Data SQLite, raw/gzip/zip) on the server through an in-memory, query-only, defensive connection with size and time caps, and emits rows in the same upload shape plus `_source_*` keys. `money_manager_planning.py` also reads its repeat rules and monthly budgets.
- **`db/`** - SQLAlchemy 2.0 models and session factory. `models.py` is the public facade over `_models/`, split by domain across `user.py`, `transactions.py`, `organization.py`, `investments.py`, `analytics.py`, `analytics_state.py`, `planning.py`, `ledger_dimensions.py`, `compensation.py`, `ai_settings.py`, `ai_usage.py`, `upload_tokens.py`, and the 2.31.0 `balance_checks.py`, `bank_alerts.py`, `category_overrides.py`, `external_refs.py`, `mf_holdings.py`, `push_subscriptions.py`, `rsu_tax.py`, `saved_view_pins.py`, `tax_ais.py`, `tax_deductions.py` and `transaction_embeddings.py` (14 tables from `feature_domains_2026`; `EmbeddingVector` is pgvector `vector(512)` on PostgreSQL, float32 bytes on SQLite). Consumer code imports from `ledger_sync.db.models`, never directly from `_models`. Financial data is user-scoped. Since PR #250 (2026-09-18, revision `domain_storage_cutover_2026`) salary structure, RSU grants, AI settings, and credit-card limits live in their own tables (`_models/compensation.py`, `_models/ai_settings.py`, services in `services/`); the old `user_preferences` JSON columns were dropped. `growth_assumptions` is still JSON in a `TEXT` column.
- **`schemas/`** - Pydantic models for request/response validation. Includes `upload.py` with `TransactionRow` and `TransactionUploadRequest` for whole-batch JSON validation, `goals.py` for goal mutations, and `salary.py` with `SalaryComponents`, `RsuGrant`, `GrowthAssumptions` schemas for tax projection inputs.
- **`services/`** - Cross-router workflows, including immutable OAuth identity resolution in `auth_service.py` (refresh-token rotation in the `auth_refresh.py` mixin, account delete/reset in `auth_account_data.py`) and user-scoped goal mutation behavior in `goal_service.py`. `money_manager_import.py` imports a backup as a snapshot (unchanged/preview/guarded commit, account settings, analytics refresh), with `money_manager_planning.py`, `money_manager_schedules.py` and `external_ref_sync.py` adding its repeat rules and budgets; `upload_tokens.py` creates, lists, revokes and authenticates hashed single-scope `lsu_` tokens; `budget_service.py` and `semantic_search_*.py` back the budget and Smart search endpoints.
- **`config/`** - `settings.py` is Pydantic BaseSettings; env vars carry the `LEDGER_SYNC_` prefix (e.g., `LEDGER_SYNC_DATABASE_URL`, `LEDGER_SYNC_JWT_SECRET_KEY`). `push_settings.py` (`LEDGER_SYNC_VAPID_PUBLIC_KEY`, `_PRIVATE_KEY` and `_SUBJECT` turn phone alerts on; `CRON_SECRET` gates the daily run) and `embedding_settings.py` (`LEDGER_SYNC_EMBEDDING_*`) are separate classes: set them as real environment variables, never in `backend/.env`, where `Settings` rejects them and the error echoes the value. [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) has the VAPID key generator.

### Key Patterns

- **Data deduplication**: Capture version-2 source fingerprints before categorization rules, using canonical JSON encoding of user, date, amount, account, note, source category/subcategory, type, explicit destination, currency, and occurrence. Public transaction IDs never change on recategorization. Legacy IDs are adopted only after verified matches; ambiguous historical duplicates reject the snapshot. Rows from a source with its own IDs (Money Manager) carry `(source_system, source_uid)`, matched first and unique per user (`core/source_identity.py`): the UID's stored row is updated in place, date/amount/account included, so its ID survives edits; a UID-less stored row is adopted once when its loose shape (date, amount, account, type, transfer ends) is unique on both sides. Account/category dimension references are user-qualified and retain original transaction labels.
- **Analytics publication**: Writers lock the user before reading/mutating analytics inputs and mark ledger/preference changes in the same transaction. `core/analytics/refresh.py` owns durable versions and dirty dates; `refresh_analytics()` skips current generations and selectively rebuilds daily/monthly summaries. Other domains still rebuild on invalidation. Use `run_full_analytics()` for explicit recovery. New input writers must invalidate before commit.
- **Backend execution boundaries**: Keep sync-only SQLAlchemy routes synchronous; use a complete worker phase for database work in async workflows. Upload orchestration lives in `services/upload_service.py`. Never await a provider with an idle authentication transaction or use one session concurrently. Startup DDL is disabled by default; apply Alembic before starting the backend.
- **Database**: SQLite for development (`./ledger_sync.db`), Neon PostgreSQL for the hosted deployment. Alembic manages schema evolution; startup `init_db()` creates missing tables but does not migrate existing columns. SQLite connections apply WAL mode, 64MB cache, NORMAL sync, and foreign-key enforcement. PostgreSQL pooling is configurable through `LEDGER_SYNC_DB_*` settings (pool_size, max_overflow, pool_recycle_seconds, connect_timeout_seconds, statement_timeout_seconds, idle_transaction_timeout_seconds; defaults 5/3/300/10/30/60). Transaction-local timeouts support Neon's PgBouncer pooler. Dialect verification uses native PostgreSQL locally and in CI.
- **Database-agnostic SQL**: SQLite uses `strftime()`, PostgreSQL uses `to_char()`. Always use `query_helpers.py` helpers (`fmt_year_month`, `fmt_year`, `fmt_month`, `fmt_date`) instead of `func.strftime()` directly -- raw SQLite SQL will break production.
- **DB URL normalization**: `session.py` auto-converts `postgresql://` and `postgresql+psycopg2://` to `postgresql+psycopg://` (psycopg v3 driver).
- **Security**: Slowapi protects token refresh and OAuth authorize/callbacks by IP, plus upload and Bedrock chat by authenticated user and IP, and AI tool execution by user. Security headers, query timeouts, one-use browser-bound OAuth state, server-side token revocation, and user-scoped data access are required. SheetJS is pinned from the vendor CDN package. Current AI API-key writes use authenticated v3 AES-256-GCM envelopes with HKDF-SHA256 and a dedicated key; legacy v1/v2 reads require successful authentication before rewrapping. Bedrock quota reservations live in the database across serverless instances.

## New Feature Patterns

- **New API endpoint**: Router in `api/`, business logic in `core/`, schema in `schemas/`. No business logic in routers. Always prefix routes with `/api/...` in the router prefix for consistency (`POST /mcp` is the one exception). Add a `DEMO_ROUTES` entry for each GET a page makes. A token route depends on `require_token_scope(scope)`; add a new scope to `TOKEN_SCOPES` in `db/_models/upload_tokens.py` first.
- **New DB model**: Add to appropriate `db/_models/` file (e.g., `user.py`, `transactions.py`). Re-export from `db/_models/__init__.py`. The `db/models.py` facade picks it up automatically. Always create an Alembic migration. A table no older backend names ships expand-only (see `feature_domains_2026`): import and reset paths that touch it tolerate its absence (`has_table`, `_delete_if_migrated`), since Vercel can serve the code before CI migrates.

## Toolchain Gotchas

- **Local PostgreSQL test runs need pgvector** (`transaction_embeddings` has a `vector(512)` column) installed for the PostgreSQL major behind `LEDGER_SYNC_TEST_POSTGRES_URL`. Fixtures create the extension inside a per-test schema, so never `alembic upgrade` that database into `public`; if a stray `vector` extension lands there, run `DROP EXTENSION vector CASCADE`.
